# ADR 0018 — Tags

- **Status:** Accepted
- **Date:** 2026-11-19
- **Amends:** ADR 0007 d5 ("no tags beside categories"). **Builds on:** ADR 0001 d1, which named tags as part of the core blog.

ADR 0007 left tags out: one way of grouping was enough until it was not. The
owner decided it is not. The audience comes from WordPress, where most blogs
carry tags, and an import that drops them loses part of how a site is found and
read.

## Decisions

### d1. A tag is a word on the entry, like a category

Tags are names typed on an entry, separated by commas, at most twenty. Two
spellings that share an address are one tag. There is no separate list of tags
to keep in step. A type keeps tags when it keeps categories: one setting,
"grouped by category and tag".

### d2. Each tag has its list

`/blog/tag/oak/`, paged like a category, headed `#oak`, in the sitemap. An
entry shows its tags after its categories, each a link to that list. The feed
names tags as Atom categories, as it names categories.

### d3. The import brings them, and their old addresses

WordPress tags come over with their posts. The old archive (`/tag/oak/`) leads
to the new list, and links and menu items that pointed at it are rewritten. A
category archive linked from the content is rewritten the same way. A post that
becomes an entry of a section of its own (ADR 0016) loses its tags, and the
owner is told.
